# 한국형 V2X 자율주행 평가 PoC — 본격 추진을 위한 인력 산정 보고

**작성일**: 2026-06-02
**대상**: 전무님
**작성 배경**: NVIDIA Alpamayo 1.5 + Cosmos-Reason2 기반 KATECH 평가 PoC 프로토타입을 작성자가 **단독으로 구축**하여 시연 가능한 수준까지 도달하였습니다. 그 과정에서 "본격 PoC 단계로 진화시키려면 1인 개발로는 불가능하며, 별도의 기획·디자인·퍼블 영역과 개발 2인 체제가 필요하다"는 결론에 도달하였습니다. 본 보고서는 그 인력 산정 근거와 3개월 일정 계획을 정리한 것입니다.

---

## 1. TL;DR

- 작성자가 단독으로 구축한 **1인 prototype**은 NVIDIA stack의 가능성을 확인했고 KATECH 시연 가능한 수준에 도달했습니다.
- 그러나 이를 **본격 PoC로 진화**시키려면 **기획·디자인·퍼블 영역의 부재**가 결정적 병목이 되며, 개발도 1인으로는 불가능합니다.
- 본격 PoC 추진을 위해 **개발자 2 + 기획자 1 + 디자이너 1 + 퍼블리셔 1 = 총 5명 × 3개월 (15 man-month)** 투입을 건의드립니다.

---

## 2. 현황 — 1인 prototype의 성과

작성자가 단독으로 구축한 결과물:

| 구성 요소 | 내용 |
|---|---|
| 모델 통합 | Alpamayo 1.5 (10B VLA) + Cosmos-Reason2 8B (VLM) 적재·추론 |
| NRE Closed-Loop | 8 rollout 사전 렌더링 (60-80분 오프라인 → 즉시 재생) |
| 평가 탭 | 6종 (시나리오 단건 / 자동 시연 / 인터랙티브 / VQA / 카메라 입력 개수 / NRE Closed-Loop) |
| 시나리오 | 20개 한국형 V2X 시나리오 (작성자 단독 설계) |
| 시연 인프라 | FastAPI + HTMX + cloudflared tunnel 운영 |
| 사용 가이드 | 8개 섹션 + 16장 자동 캡처 스크린샷 |

**의의**: NVIDIA Alpamayo stack이 한국형 V2X 평가에 **실제로 적용 가능함**을 확인했고, KATECH 시연 가능한 수준에 도달했습니다.

**한계**: 1인 prototype의 본질적 한계로 인해, 본격 PoC 단계로 그대로 가져갈 수 없습니다 (다음 절).

## 3. 1인 prototype의 한계 — 왜 본격 PoC로 진화시켜야 하는가

작성자가 단독으로 구축하는 과정에서, 1인 개발만으로는 채울 수 없는 영역이 명확히 드러났습니다.

### 3-1. 기획 부재
- 시나리오 20개의 가설·V2X 메시지·기대 결과가 **작성자 주관**에 의존
- KATECH 평가위원 페르소나·사용자 분석이 비공식 추정에 의존
- 평가 지표(ADE / FDE / counterfactual) 정의가 기술적 편의에 치우침
- → **KATECH가 합의한 시나리오**가 아니므로 평가 결과의 권위가 부족

### 3-2. 디자인 부재
- 정보구조도·와이어프레임 없이 작성자가 즉흥 설계
- 시각 디자인이 일관성 없음 (컬러·타이포·차트 톤이 탭마다 상이)
- 평가위원의 **인지 부하**가 높음 → 5분 내 가치 전달이 어려움
- BEV·차트·표의 시각적 신뢰도가 양산급 결과물 대비 낮음

### 3-3. 퍼블 부재
- 반응형이 일부 화면만 적용 (모바일·저해상도 깨짐)
- 접근성(WCAG) 미고려
- 브라우저 호환성 검증 안 됨
- 컴포넌트 재사용 구조가 약함 → 시나리오 추가 시 코스트 증가

### 3-4. 개발 1인의 한계
- 백엔드(모델 통합) + 프론트(HTMX) + 시스템(cloudflared·캐싱) + 운영(자동 캡처)을 **동시에 진행 불가능**
- 한 영역에 집중하면 다른 영역이 정체
- 회귀 테스트·부하 테스트·다중 세션 격리가 누락됨
- → 시연 중 장애 발생 시 즉시 대응할 인력이 없음

## 4. 본격 PoC 구성 — 5개 역할의 협업 흐름

```
[기획]  →  [디자인]  →  [퍼블]  →  [개발]
  ↑                                     ↓
  └──────── 피드백 루프 ────────────────┘
```

- **기획자**가 시나리오·지표·사용자 흐름을 정의
- **디자이너**가 정보구조·시각 디자인·컴포넌트 시스템 설계
- **퍼블리셔**가 디자인을 마크업으로 구현 (반응형·접근성 포함)
- **개발자 2인**이 모델 통합·시스템 운영을 분담
- 매주 피드백 루프로 평가위원 입장에서의 가치 정렬

각 역할이 빠지면 본 보고서 3절의 한계가 그대로 재현됩니다. 5개 역할은 **서로 대체 불가능**입니다.

## 5. 역할별 R&R

### ① 개발자 1 — 백엔드 · 모델 통합 (Senior)
**책임 영역**
- Alpamayo 1.5 / Cosmos-Reason2 적재·추론 파이프라인
- FastAPI 백엔드, ASL 프로토콜 파서, vllm 통합
- NRE Closed-Loop 연동, 사전 캐싱 파이프라인
- 모델 회귀 테스트, 운영 매뉴얼

**핵심 산출물**: 모델 inference API · NRE 파이프라인 · 캐싱 시스템 · 운영 매뉴얼

### ② 개발자 2 — 프론트 · 시스템 (Mid–Senior)
**책임 영역**
- HTMX 흐름 제어, 상태 관리, 라우팅
- 자동 시연 / 인터랙티브 / VQA / 카메라 sweep 통합
- 자동 캡처 파이프라인, cloudflared tunnel 운영
- 부하 테스트, 다중 세션 격리

**핵심 산출물**: 통합 평가 플랫폼 · 자동 캡처 파이프라인 · 운영 인프라

### ③ 기획자 1
**책임 영역**
- KATECH 평가위원 페르소나·사용자 분석
- 한국형 V2X 시나리오 카탈로그 (가설·메시지·기대 결과)
- 평가 지표 정의 (ADE / FDE / 카메라 sweep / V2X counterfactual)
- 6 평가 탭의 사용자 흐름·정보 구조 설계
- KATECH와 시나리오 공동 정의 워크샵 운영

**핵심 산출물**: 사용자 분석 · 시나리오 정의서 · 지표 정의서 · 정보구조 · 워크샵 결과물

### ④ 디자이너 1
**책임 영역**
- 정보구조도 / 와이어프레임
- 시각 디자인 (컬러·타이포·아이콘·차트)
- 컴포넌트 시스템 (재사용 가능한 카드·표·BEV 시각화 톤)
- 사용 가이드 디자인, 발표 자료 디자인

**핵심 산출물**: IA · 와이어프레임 · 비주얼 가이드 · 컴포넌트 시스템 · 발표 자료

### ⑤ 퍼블리셔 1
**책임 영역**
- 디자인 시스템 → HTML/CSS 마크업 구현
- 평가 탭 6종 퍼블리싱
- 반응형, 접근성 (WCAG), 브라우저 호환성
- 사용 가이드 페이지, 최종 검수

**핵심 산출물**: 마크업 셋 · 퍼블 가이드 · 접근성 보고서

### 마일스톤
- **M1 (1개월 말)**: 기획·디자인 80% 완료 + 개발 골격 동작 (단일 탭 end-to-end)
- **M2 (2개월 말)**: 6 평가 탭 통합 완료 + KATECH 시나리오 합의
- **M3 (3개월 말)**: 안정화 완료 + 발표 자료 + 평가위원 시연 준비 완료

## 7. 전무님께 드리는 권고

### 7-1. 인력 확보
1. **개발자 2명 우선 확보** — 모델 통합 Senior 1명, 프론트·시스템 Mid-Senior 1명
2. **기획자 1명** — V2X·자율주행 도메인 이해 + 사용자 분석 경험
3. **디자이너 1명 + 퍼블리셔 1명** — 평가 플랫폼·대시보드 경험 우대

### 7-2. 일정 권고
- **3개월 통합 추진**이 가장 효율적 (단계별 분리 시 컨텍스트 비용 발생)
- KATECH 공동 정의 워크샵을 **2개월차 말**에 배치 → 3개월차에 결과 반영

### 7-3. 우선순위
- **1순위**: 기획·디자인 (시나리오·정보구조) — 다른 모든 작업의 입력
- **2순위**: 개발 1 (모델 통합) — 시연 가능한 결과의 핵심
- **3순위**: 퍼블·개발 2 — 디자인·기획 산출물을 기반으로 진행

### 7-4. 리스크 관리
- **모델 stack 종속 분리**: Alpamayo·NRE에 종속되지 않게 평가 인프라(시나리오·UX·지표)를 **재사용 가능한 자산**으로 구축
- **차세대 모델 로드맵 동기화**: Alpamayo 차세대 / Cosmos-Reason 차세대 출시 시 본 PoC 위에 갈아끼울 수 있도록 인터페이스 표준화
- **KATECH 합의 시점 확보**: 2개월차 워크샵에서 시나리오·지표를 KATECH와 사전 합의해야 평가 결과 신뢰도 확보
